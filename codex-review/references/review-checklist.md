# Review Checklist Reference

按五個審查維度分類的檢查項目。載入後逐項檢查變更代碼。

---

## 1. Correctness（正確性）

- [ ] 邏輯是否正確？條件判斷、迴圈邊界、布林運算
- [ ] 錯誤處理是否完整？是否涵蓋所有失敗路徑
- [ ] 空值 / undefined / null 是否都有處理
- [ ] 陣列越界、空集合、缺失欄位等邊界情況
- [ ] 非同步操作：Promise/async 是否正確等待或捕獲錯誤
- [ ] 型別轉換是否安全（隱式轉換陷阱）
- [ ] 預設值是否合理

## 2. Security（安全性）

- [ ] 用戶輸入是否經過驗證和清理
- [ ] SQL 查詢是否使用參數化（無字串拼接）
- [ ] 是否有 command injection 風險
- [ ] 認證和授權檢查是否完整
- [ ] 敏感資料是否在日誌或回應中暴露
- [ ] API 金鑰或密碼是否硬編碼
- [ ] CSRF / XSS 防護是否到位

## 3. Performance（效能）

- [ ] 是否有 N+1 查詢問題
- [ ] 迴圈內是否有不必要的重複計算或 IO
- [ ] 記憶體使用：大集合是否串流處理
- [ ] 是否有不必要的同步等待
- [ ] 快取策略是否合理
- [ ] 資料庫索引是否覆蓋查詢模式

## 4. Maintainability（可維護性）

- [ ] 函數是否過長或職責過多（單一職責）
- [ ] 命名是否清晰表達意圖
- [ ] 是否有重複代碼可抽取
- [ ] 複雜邏輯是否有註解說明「為什麼」
- [ ] 依賴是否合理（無循環依賴、無過度耦合）
- [ ] 是否易於撰寫單元測試
- [ ] TypeScript 型別是否精確（無 any）

## 5. Compatibility（相容性）

- [ ] API 合約是否向後相容（現有呼叫方是否會中斷）
- [ ] 資料庫 schema 變更是否需要遷移
- [ ] 遷移是否可回滾
- [ ] 新舊版本同時運行時是否安全（滾動部署）
- [ ] 環境變數或配置變更是否已記錄
- [ ] 是否有已棄用的 API 需要更新呼叫方
